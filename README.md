# Система учета расходов

Индивидуальный проект, тема №14. Консольная версия до ПР3 включительно.

## Назначение
Учет личных расходов, анализ затрат по категориям и контроль месячного бюджета.

## Целевая аудитория
Студенты и другие пользователи, контролирующие повседневные траты.

## Предметная область
Личные финансы: пользователь фиксирует покупки с датами и категориями,
сравнивает общую сумму за месяц с установленным лимитом.
Превышение лимита не запрещает учет уже совершенных покупок.

## Основные сущности
- Финансовая операция (`Transaction`): ID, сумма, дата, описание.
- Расход (`Expense`): наследник операции с категорией.
- Бюджет (`Budget`): лимит расходов на конкретный месяц.
- Система учета (`ExpenseTracker`): управление коллекцией расходов и бюджетов.
- Пользователь: пока один локальный пользователь; аккаунты появятся на этапе Django.

## Основные функции
1. Добавление расхода с проверкой суммы, даты, категории и описания.
2. Просмотр всех расходов, фильтрация по месяцу и категории без учета регистра.
3. Изменение расхода по ID (вводятся все новые значения).
4. Удаление расхода по ID с подтверждением.
5. Установка и изменение бюджета на выбранный месяц.
6. Отчет: общая сумма, суммы по категориям, остаток и состояние бюджета.
7. Автоматическое сохранение после каждого изменения и загрузка при запуске.

## Запуск
Нужен Python 3.10 или новее; сторонних библиотек нет.
Откройте терминал в папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe main.py
```

Если `py` отсутствует, используйте `python` установленного Python.
В IDE выберите интерпретатор `.venv\Scripts\python.exe`.
Окружение создается на каждом компьютере заново и не входит в архив.

Суммы вводятся в рублях: `750`, `750.50` или `750,50`.
Внутри используются целые копейки, при вводе используется `Decimal`.
Суммы расходов и бюджетов должны быть положительными.
Дата: `2026-09-22`; месяц: `2026-09`. Enter в поле даты означает сегодня.
Категория и описание обязательны. Ошибка ввода возвращает в меню.

Данные хранятся в `data/expenses.json` рядом с `main.py` независимо от папки
запуска. Первый запуск создает пустую систему, файл появляется после изменения.
При поврежденном JSON запуск прекращается без его перезаписи. Запись идет через
временный файл; при ошибке сохранения изменение не применяется в памяти.
Программа предназначена для одного одновременно запущенного экземпляра.
Для резервной копии достаточно скопировать файл JSON после сохранения.

## Структура
```text
main.py                       запуск
expense_tracker/models.py     сущности и проверка значений
expense_tracker/service.py    операции с расходами и отчетность
expense_tracker/storage.py    хранение в JSON
expense_tracker/cli.py        меню и пользовательский ввод
tests/test_tracker.py         автоматические проверки
GUIDE.md                      демонстрация и объяснение ООП
```

## Соответствие этапам
- ПР1: простые типы, арифметика, преобразования, ветвления, функции, импорт,
  README и Git. Отдельная начальная версия сохранена в Git под тегом `pr1`.
- ПР2: списки, словари, множество ID, циклы, функции, модули, файлы,
  исключения и аннотации типов реализованы в текущей версии.
- ПР3: классы и объекты; наследование `Expense(Transaction)`;
  полиморфизм через переопределение `summary()`; инкапсуляция закрытыми
  атрибутами и свойствами без сеттеров.

Основание: раздел 6 и план развития из предоставленной методички ПР1.
Отдельные методички ПР2 и ПР3 не предоставлены; их дополнительные требования
потребуют отдельной сверки. Тег отдельной процедурной версии ПР2 не создавался.
