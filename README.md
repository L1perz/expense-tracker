# Система учета расходов

Индивидуальный сквозной проект, тема №14. Практическая работа №1:
«Основы Python: актуализация знаний и настройка рабочего окружения».

## Назначение

Приложение помогает учитывать личные расходы и контролировать месячный бюджет.
Пользователь видит, сколько денег потрачено и сколько осталось после покупки.

## Целевая аудитория

Студенты и другие пользователи, желающие контролировать повседневные траты.

## Предметная область

Личные финансы. Каждая трата имеет сумму, дату, категорию и описание.
Расходы сравниваются с бюджетом на месяц. Превышение бюджета не запрещает
учет уже совершенной покупки, но сопровождается предупреждением.
Все суммы в начальной версии выражаются в рублях.

## Основные сущности

- Пользователь: владелец расходов и бюджета; отдельные аккаунты появятся позднее.
- Расход: сумма, дата, категория и описание покупки.
- Категория: группа расходов, например продукты, транспорт или учеба.
- Бюджет: лимит расходов пользователя на выбранный месяц.

Это сущности предметной области; классы и модели базы данных на ПР1 не создаются.

## Основные функции

На ПР1 реализованы:

1. Ввод и проверка одного расхода: сумма, категория, описание, текущая дата
   (`main`, `read_money`).
2. Расчет общей суммы затрат с учетом нового расхода (`calculate_total`).
3. Расчет остатка месячного бюджета (`calculate_remaining`).
4. Проверка лимита с тремя результатами: деньги остались, бюджет исчерпан,
   бюджет превышен (`get_budget_status`).

## Начальный сценарий

Пользователь вводит бюджет на текущий месяц, сумму ранее совершенных расходов
за этот же месяц и новую покупку. Программа проверяет данные и выводит итог.
Ввод ранее потраченной суммы вручную заменяет хранение истории на этапе ПР1.
Каждый запуск независим; файлы с расходами и база данных пока не используются.
При ошибке ввода программа объясняет проблему и завершает работу.

Деньги внутри программы хранятся целыми числами в копейках, чтобы избежать
неточностей арифметики `float`. Разрешены точка или запятая и до двух знаков
после разделителя. Бюджет и новый расход должны быть больше нуля;
ранее потраченная сумма может равняться нулю.

Использованы `str`, `int`, `bool`, арифметика, преобразование типов,
ветвления, функции и импорт `date` из стандартного модуля `datetime`.
В коде нет циклов, коллекций и собственных классов.

## Запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не требуются.
Откройте терминал в папке проекта. Команды для Windows:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe main.py
```

Если команда `py` отсутствует, используйте команду `python` установленного Python.
В IDE выберите интерпретатор `.venv\Scripts\python.exe`.
Виртуальное окружение создается заново на каждом компьютере и не входит в архив.

## Пример

Вход: бюджет `10000`, ранее потрачено `2500`, новый расход `750,50`,
категория `Продукты`, описание `Покупка продуктов`.

Результат: всего потрачено `3250.50 руб.`, остаток `6749.50 руб.`,
сообщение `Расход в пределах бюджета.` Дата берется с компьютера при запуске.

## План развития

- ПР2: список расходов, циклическое меню, поиск и фильтрация, сохранение в файл,
  обработка исключений, разделение программы на модули.
- ПР3: классы расходов, категорий и бюджета.
- ПР5–6: Django-приложение, страницы списка расходов и сводки бюджета.
- ПР7–9: база данных, связи сущностей, запросы ORM и административный интерфейс.
- ПР10: формы создания, просмотра, изменения и удаления расходов.
- ПР11: регистрация, вход и доступ только к собственным данным.
- ПР13–15: автоматизированные тесты функций и веб-приложения.
- Дальнейшие этапы: REST API, отчеты по категориям, Docker и CI/CD.
