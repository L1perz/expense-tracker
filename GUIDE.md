# Подготовка к демонстрации ПР1

## Что подготовлено

Код начального сценария, README по разделу 6.4, .gitignore и эта инструкция.
Проект соответствует объему ПР1: один расчет и четыре прикладные функции.
Согласование темы и выполнение Яндекс Практикума подтверждает сам студент.

## Проверка программы

При каждом запуске вводите бюджет, предыдущие расходы, новый расход,
непустые категорию и описание.

| Бюджет | Ранее потрачено | Новый расход | Ожидаемый итог |
| --- | --- | --- | --- |
| 10000 | 2500 | 750,50 | Всего 3250.50; остаток 6749.50 |
| 1000 | 700 | 300 | Остаток 0.00; бюджет исчерпан |
| 1000 | 900 | 250 | Остаток -150.00; превышение 150.00 |
| 1 | 0,10 | 0,20 | Всего 0.30; остаток 0.70 |
| 1000 | 0 | -5 | Сообщение об ошибке |
| 1000 | 0 | abc | Сообщение об ошибке |
| 1000 | 0 | 1,234 | Сообщение об ошибке |

Пустая категория или описание также должны приводить к сообщению об ошибке.

## Отладка в IDE (раздел 6.6)

Эти действия нужно выполнить и показать самостоятельно; инструкция не является
подтверждением проведенной вами отладки в IDE.

1. Откройте папку проекта в PyCharm или VS Code с поддержкой Python.
2. Создайте окружение по README и выберите его интерпретатор.
3. Поставьте breakpoint на строку `return budget - total_spent`
   в функции `calculate_remaining` (щелчком слева от номера строки).
4. Запустите `main.py` в режиме Debug. Введите `10000`, `2500`, `750,50`,
   `Продукты`, `Покупка продуктов`.
5. На остановке проверьте значения: `budget = 1000000`,
   `total_spent = 325050`. Значения представлены в копейках.
6. Выполните шаг с выходом из функции (Step Out). Убедитесь, что после
   присваивания `remaining = 674950`. Продолжите до вывода результата.
7. Для учебной ошибки замените вычитание на сложение:
   `return budget + total_spent`.
8. Повторите отладку с теми же данными. Ошибочный остаток равен
   `1325050` копеек: расходы увеличивают остаток вместо уменьшения.
9. Исправьте оператор обратно на `-`, повторите запуск и проверьте `6749.50`.
10. При необходимости сделайте собственные снимки breakpoint, переменных
    и исправленного результата для защиты.

## Git (разделы 6.3 и 6.7)

Если открытая папка содержит `.git`, репозиторий уже создан. Проверьте:

```powershell
git status
git log --oneline
```

Для копии без `.git` создайте репозиторий:

```powershell
git init
git add README.md .gitignore main.py GUIDE.md
git commit -m "Реализован начальный сценарий учета расходов для ПР1"
git status
git log --oneline
```

Если Git запрашивает имя и почту, задайте свои реальные данные командами
`git config user.name` и `git config user.email` с соответствующим значением
в кавычках, затем повторите commit.
Удаленный репозиторий необязателен по разделу 6.7, если он не используется.
Если преподаватель требует ссылку, создайте свой репозиторий на выбранном
сервисе и отправьте в него этот проект. Адрес и учетные данные в заготовку
не подставлены.

## Краткие ответы для защиты проекта

- Задача: учитывать траты и контролировать остаток месячного бюджета.
- Пользователи: люди, ведущие учет личных финансов, в том числе студенты.
- Сущности: пользователь, расход, категория и бюджет.
- Сценарий ПР1: ввод покупки, расчет суммарных расходов и остатка, проверка лимита.
- Зачем функции: разделяют ввод, расчеты и определение состояния бюджета.
- Зачем импорт: `date.today()` получает текущую дату из стандартной библиотеки.
- Зачем копейки: арифметика целых чисел позволяет считать суммы точно.
- Что будет дальше: хранение истории, классы, Django, база данных и аккаунты.
- Почему подходит для веб-приложения: расходы пользователя связаны с категориями
  и бюджетами; нужны формы, база данных и разграничение доступа.
