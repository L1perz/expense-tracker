# Демонстрация и защита проекта

## Сценарий проверки
1. Запустите main.py. Пункт 5: месяц 2026-09, бюджет 10000.
2. Пункт 1: сумма 2500, дата 2026-09-01, категория Продукты, описание Закупка.
3. Пункт 1: сумма 750,50, дата 2026-09-22, категория Транспорт, описание Проезд.
4. Пункт 6, месяц 2026-09: всего 3250.50 руб., остаток 6749.50 руб.
5. Пункт 2: проверьте список, затем фильтр по категории транспорт.
6. Выйдите через 0 и запустите снова: расходы и бюджет должны сохраниться.
7. Пункт 3: измените расход по его ID; проверьте отчет.
8. Пункт 4: удалите расход с подтверждением; проверьте список.
9. Введите неверную сумму или дату: программа объяснит ошибку и вернется в меню.

## Устройство программы
`main.py` вызывает меню. Меню передает запросы объекту `ExpenseTracker`.
Система хранит список объектов `Expense` и словарь объектов `Budget`.
`JsonStorage` переводит состояние в JSON и восстанавливает объекты при запуске.
Расчет отчета отделен от консольного ввода.

### ООП на примере проекта
- Класс: описание сущности; объект: конкретный расход, созданный через Expense.
- Наследование: Expense наследует ID, сумму, дату и описание от Transaction.
- Инкапсуляция: поля с двумя подчеркиваниями изменяются внутри класса;
  свойства позволяют прочитать их, а валидаторы проверяют создание объектов.
  Это механизм организации кода, а не защита данных от злоумышленника.
- Полиморфизм: у Transaction и Expense есть метод summary(); при вызове
  у объекта Expense используется переопределенная версия с категорией.
- Композиция: ExpenseTracker содержит объекты расходов и бюджетов.

Категория пока является строкой, отдельного класса пользователя пока нет.
Это локальное приложение для одного человека без авторизации.

## Отладка в IDE
Нужно выполнить самостоятельно и показать преподавателю. Эти инструкции
не утверждают, что вы уже прошли отладку.

1. Откройте проект в IDE с Python и выберите виртуальное окружение.
2. Поставьте breakpoint в models.py в Budget.remaining на строке
   `return self.limit - spent`.
3. Запустите main.py в режиме Debug и выполните шаги 1–4 сценария выше
   на чистых данных (либо используйте фактические суммы своего набора).
4. На остановке проверьте self.limit = 1000000 и spent = 325050 (копейки).
5. Выполните Step Out: остаток должен быть 674950, в отчете 6749.50 руб.
6. Внесите учебную ошибку: замените минус на плюс в Budget.remaining.
7. Повторите отчет: ошибочный остаток составит 13250.50 руб.
8. Найдите ошибку пошагово, верните минус и проверьте правильный результат.
9. При необходимости сделайте собственные скриншоты остановки и переменных.

## Git
В архив включен локальный репозиторий с исходной версией ПР1 и итоговой ПР3.
Проверьте состояние и историю:

```powershell
git status
git log --oneline
git show pr1:main.py
```

Последняя команда показывает начальный код без изменения текущих файлов.
Удаленный репозиторий не создан. Если нужна ссылка для сдачи, создайте свой
репозиторий на выбранном сервисе и отправьте туда этот локальный репозиторий.
