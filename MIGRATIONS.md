# Модели и миграции

Модели находятся в приложениях своей предметной области:

| Приложение | Модель | Таблица |
| --- | --- | --- |
| users | User | ledger_user |
| categories | Category | ledger_category |
| accounts | Account | ledger_account |
| operations | Operation | ledger_operation |

Имена таблиц сохранены через `Meta.db_table`. Пользователь финансового счёта
`users.User` отделён от учётной записи `django.contrib.auth` для входа в админку.
Веб-страницы справочников имеют собственные `urls.py` и `views.py`.
Публичные адреса `/users/`, `/categories/`, `/accounts/` и `/operations/` сохранены.

## Новая установка

Обычная команда `python manage.py migrate` применяет историческую схему ledger,
нормализацию категорий и перенос состояния моделей. После неё можно выполнить
`python manage.py import_legacy` для демонстрационных JSON. Не нужны `--fake`,
ручное создание таблиц или удаление старых миграций.

## Обновление существующей установки

Сначала сделать резервную копию базы SQLite и каталога `media`. Затем обновить
код и выполнить `python manage.py migrate` до перезапуска сервера. Повторять
`import_legacy` в уже заполненной базе не нужно.

`ledger.0001` и `ledger.0002` оставлены неизменными. Начальные миграции новых
приложений зависят от `ledger.0002` и меняют только состояние моделей Django.
`ledger.0003` убирает старые модели из состояния ledger, затем переносит
ContentType в новые приложения. Существующие таблицы и финансовые записи не
пересоздаются и не копируются. Права сотрудников после переноса называются,
например, `operations.view_operation`, а ID назначенных прав сохраняются.

Если начальные миграции новых приложений запускались отдельно, уже созданные
дубли ContentType и прав объединяются с прежними: назначения пользователям и
группам, а также ссылки журнала админки сохраняются.

## Проверка переноса

`tests/migration_probe.py` создаёт отдельную SQLite в прежнем состоянии, добавляет
счёт, изображение, операции всех статусов, права сотрудника, группы и журнал.
Затем применяет новые миграции, проверяет доступ к четырём разделам админки,
откатывает перенос, повторно применяет его и проверяет внешние ключи. Содержимое
четырёх финансовых таблиц сравнивается до и после каждого этапа.

Для просмотра плана и состояния:

```bash
python manage.py migrate --plan
python manage.py showmigrations
python manage.py makemigrations --check --dry-run
python -m pytest tests/test_migrations.py -q
```

Откат схемы и откат кода должны выполняться вместе: после возврата к
`ledger.0002` используется версия кода до разделения приложений. Резервная копия
не заменяется результатами тестов.
